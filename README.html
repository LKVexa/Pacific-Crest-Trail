TRAIL DOSSIER / LOCAL TRAINING EXPEDITION

Your whole trail, one dossier at a time

The northbound trail is divided into 266 virtual daily sections: 265 sections of 10 miles, followed by a final 5.84-mile section. Each section has its own route map, geographic checkpoints, and standalone dossier.

Virtual distance and treadmill distance are separate. Ten trail miles defines the amount of route covered by one dossier. Choose your physical workout separately. You can spend several workouts or several calendar days with the same dossier.

Start your hike

  1. Keep this entire application folder in a writable location, such as your Documents folder. Extract the complete folder before launching it.
  2. Double-click Start-Hike.cmd. It starts the local service and opens the separate clean dossier window after the saved hike is ready. Your original D-drive browser is untouched.
  3. The default address is http://127.0.0.1:8765/. If you select another port, use the exact address shown by the launcher.
  4. Explore the current route and its dossier. You may also browse previous or future dossiers without changing your saved trail place.
  5. Save a preparation review or eligible walking activity, acknowledge a fictional choice or deferral, and save a reflection or deliberate empty reflection. Then acknowledge the current section and choose Complete section and continue.

Reopening the application resumes your current unfinished section. It records a new launch, and it advances only after a deliberate completion is saved. Completing a section records a virtual itinerary acknowledgement; it creates no workout or measured exercise record.

What is included

  • All 266 daily dossiers covering trail miles 0–2,655.84 northbound.
  • A separate map for every day, with the sourced trail line, start and finish symbols, north orientation, geographic reference grid, approximate scale, neighboring trail context, and a regional locator. When the topographic edition is enabled, the daily view also identifies its USGS terrain and contour source.
  • A whole-trail overview connecting the daily sections through California, Oregon, and Washington.
  • A searchable section browser, adjacent-dossier navigation, geographic checkpoint coordinates, and preparation prompts.
  • Persistent local history that survives browser refreshes, restarts, and ordinary relaunches.
  • Standalone dossiers and geometry in HTML, SVG, and GeoJSON, with a complete daily-section table.

Route: Pacific Crest Trail Association, 2026 snapshot, CC BY 4.0. Regional context: Census 2017 / us-atlas 3.0.1.

The complete itinerary is in content/itinerary.json. Individual files follow the stable pattern day-001 through day-266. Open Day 1 or open the final day as a standalone document.

Runtime requirements

  • Windows for the CMD and PowerShell launchers.
  • PowerShell permitted to run local scripts. The launcher selects installed PowerShell 7 when available, including the bundled Codex runtime if present; otherwise it selects Windows PowerShell. The application service changes no execution-policy settings. The copied vendor browser retains its existing per-process hosting invocation; machine and organizational policies are not changed.
  • Python 3.11 or newer with its standard-library sqlite3 module. No additional Python packages are required by the core service.
  • Microsoft Evergreen WebView2 for the included clean window. A modern system browser can also display the local site. Static maps and dossiers remain ordinary local files.
  • A writable application folder for the repository-local history and runtime logs.

Python selection is: the -Python launch argument, the PCT_PYTHON environment variable, config/local.json, a usable Python executable on the path, then the bundled Codex Python runtime when present.

Useful launch options

Run these from a terminal opened in this application folder:

Start-Hike.cmd
Start-Hike.cmd -NoBrowser
Start-Hike.cmd -Status
Start-Hike.cmd -Port 8787

-Status reports whether this repository has a verified running service and its completed-section count. -NoBrowser prepares the saved hike without automatically opening a browser. Selecting another port does not move or reset your hike.

To close the service, open a permitted PowerShell terminal in this folder and run:

& .\scripts\Stop-Hike.ps1

The stop script checks the application, repository, and current instance before requesting a graceful shutdown. It preserves the saved history. Closing a browser tab alone leaves the local service running.

Optional local settings go in config/local.json. This file overrides the defaults without editing them:

{

Launch arguments take precedence over the corresponding configured port and Python choices. A running verified instance is reused; stop it before asking the same repository to start on another port.

Each successful launch or reuse receives its own run identity. Hike sections use separate completion records, so launching twice in one day cannot complete two sections. Calendar dates do not determine expedition progress.

A completion commits its receipt, section status, and continuation pointer together in SQLite. Repeating the same save replays the receipt. A stale tab or conflicting save must refresh the saved trail place before advancing another section.

If a save’s response is lost, use Check and retry this save. The browser checks the same operation identity instead of issuing a second completion. The server’s committed history remains authoritative.

To back up or move the application: close it with the stop script, wait for confirmation, then copy the whole application folder including data/. Keep the pinned itinerary with its database. Restore the complete copy before relaunching.

The database pins the exact itinerary file by SHA-256. Replacing or editing it in place will produce a compatibility refusal instead of silently changing the meaning of completed days. Restore the original content or use a fresh distributed application folder for a separate hike.

Where the maps come from

The route uses the Pacific Crest Trail Association’s centerline and 2026 half-mile markers, downloaded on October 2, 2026 UTC. PCTA publishes these data under Creative Commons Attribution 4.0 International. Its January 2026 published whole-trail estimate is 2,655.84 miles.

This application divides the northbound centerline at marker-calibrated virtual mile positions. Adjacent sections share identical boundary coordinates, and the full mileage range is covered once. The final section is trail miles 2,650–2,655.84.

The source line contains 1,210,247 vertices. The display geometry uses a four-metre simplification tolerance while preserving daily endpoints. Route-only maps use a local, north-up equirectangular projection; their geographic scale is approximate. The topographic edition places the same route and checkpoints over the USGS topographic basemap with its published geographic extent. The whole-trail locator is more generalized.

Topographic daily maps include terrain shading and contours as historical geographic context. Each enabled map displays its source and retrieval snapshot. Contour detail and interval vary with location and zoom. Elevation-label units in the raster source are not assumed; use the supplied map notes and source labels. Basemap retrieval dates are not terrain survey dates. Cached daily maps remain local; viewing them does not require internet access.

Regional context uses generalized 2017 U.S. Census state boundaries redistributed by us-atlas 3.0.1. Its ISC notice is retained in LICENSES.txt.

Changes to the route data include daily segmentation, marker calibration, display simplification, SVG rendering, and regional locator composition. Attribution and the modification notice appear in the dossiers and maps.

Map interpretation: daily endpoints are virtual checkpoints. They are not verified campsites, trailheads, water sources, or recommended real-world stopping places. Topographic context does not establish current weather, closures, water or campsite availability. The maps do not prescribe treadmill incline or calculate a physical training target or verified elevation gain.

Nine source marker records labelled 2,656–2,660 had no spatial geometry and were excluded from spatial calibration. Source service prose still said 2025 while the geometry edit date and PCTA publication identified January 2026. The exact downloaded bytes and these dispositions are recorded in the source audit.

The daily experience

The default window stays at http://127.0.0.1:8765/. It has no browser toolbar, address field, search bar or tab controls. The Itinerary button opens the dossier's retained search field. Future and completed dossiers are read only. Source links open in your system browser without changing the dossier window's address. A nondefault development port opens in the system browser.

Assignments and measurements come from you. Actual activity is manual self-report, not treadmill telemetry. Missing distance or duration stays unknown. A preparation review adds no physical mileage. Story choices use explicitly fictional planning tokens and insight stamps, and never change a physical target. Saved reflections retain append-only versions; an empty reflection requires deliberate acknowledgement. Nothing advances automatically because you open, refresh, close or relaunch.

Real records and fictional progress are separate. You can progress through preparation even when a physical assignment remains unmet; this never marks that assignment physically complete. The current build has no automatic equipment control, training prescriptions, interval timer, activity corrections, arbitrary route editing, southbound mode, character graph, typed food/water inventory or complete knowledge assessment system.

Photographs and look-arounds

The location-assigned photo edition supplies at least 10 local photographs for every one of 266 daily legs. Use the numbered thumbnail gallery to choose a view. Each image is clearly labeled Ground photograph or Aerial photograph, with its location, source and separate source license. Maps and look-around links do not count toward this minimum.

A licensed ground photograph is assigned once to its globally nearest route section within 1 km, using the archived provider geotag. A geotag can describe the camera or subject; the application does not claim independent camera-position verification. Missing ground views are filled with distinct, untouched USGS aerial-image tiles. An aerial tile has an exact geographic extent, a center within 500 m of its assigned section, and a route witness inside its bounds. Its caption describes an overhead area containing the trail. No duplicate source or byte-identical image counts as another photograph. Source dates and image capture dates are distinct.

The photographs and both map styles are cached locally for offline viewing. Source pages, public social links and interactive panorama services need internet. Each section retains three Google Street View discovery links, for798 checkpoints. No Google panorama coverage is verified; a location link may return a nearby panorama or no image. The three separately attributed spherical source pages retain their original association and untested-viewer status. Historical imagery does not establish current conditions or visibility.

Inspect content/visuals.json, content/leg_photo_manifest.json and their exact archived public source metadata. Run python scripts/Expand-Leg-Photos.py --offline to reproduce the photo edition from the verified cache. Public photo acquisition is deliberate and never runs automatically from the launcher.

Topographic and Satellite map views

The map's Topographic / Satellite toggle changes only its background imagery. The same route, mile boundaries, start and finish remain in place. The chosen view is a local display preference; toggling adds no workout or hike completion. Satellite mode includes historical aerial orthoimagery from USDA / USGS, with lower-resolution cached source tiles where detailed imagery is unavailable.

Topographic maps contain official contours and shaded relief. Contour intervals and raster label units are source-dependent; no route elevation gain or treadmill incline is calculated. Satellite tiles use their official Web Mercator matrix and geographic bounds; local map interpolation error is checked against a quarter-pixel limit. The whole-trail locator remains a geographic route overview.

Private export and consistent backups

Use the following commands with a new output name each time. Exports intentionally include your private notes; they exclude service credentials. Backups use SQLite's consistent backup mechanism, retain campaign/experience history and the pinned route/source package, and validate restoration. Restore refuses an existing target and never overwrites active history.

python app/history_tools.py export --data-dir data --output exports/my-history.json
python app/history_tools.py backup --data-dir data --destination backups/my-backup
python app/history_tools.py restore --backup-dir backups/my-backup --data-dir restored-history

A database recovery backup is distinct from the whole application distribution. For relocation, stop the service, close the dossier window, and copy the entire project including its data/, content/ and copied browser. Keep one active authoritative folder at a time. OneDrive is the requested storage location, but live multi-computer SQLite synchronization is not supported or validated; stop the local service before moving a synchronized copy to another computer.

Isolated tests are included under tests/. They create synthetic fixtures and do not use your saved hike. Verification reports state their tested scope; institutional signoffs and missing systems remain open.
